Guide: what each part proves

The 10-node gateway path

Every request walks the same trace: authenticate, rate limit, input guardrail, route, cache, budget, model, output guardrail, answer, log. One node is italicized — it is the only one that "calls" a model. The other nine are the control layer the article is about.

Cost-tier routing

The router picks the cheapest tier that can handle the task: classify and extract go to nano, summarize to standard, reason to pro. Paste a prompt over 600 characters and watch the tier bump — input length is a routing signal, not just an invoice line. Check "standard tier down" and a summarize request falls back to pro, flagged in the trace. The caller never had to know.

Inference economics

Every metered call reports tokens in/out and a dollar cost from the tier's per-1K prices. Run "Classify a support ticket" then "Same ticket, again": the repeat is a cache hit — $0.00, 6ms. Switch to the sandbox key and ask it to reason: the projected cost exceeds its $0.10 cap, so the budget node denies the request before a cent is spent.

Guardrails on both sides

The injection scenario is denied at the input guardrail — no model call, no spend. The API-key probe is more interesting: the prompt matches no input rule, but the simulated model still leaks a fixture credential, and the output guardrail redacts it. Input filters alone are not enough.

Observability

The request log records every call — denied, rate-limited, over-budget, cached, or answered — with the model, cost, and verdict. Burst ×5 with the sandbox key (limit 3/minute) and watch the fourth and fifth requests get denied while still leaving trace records.

Honest limits

No real model is called; token counts, prices, and latency are formulas. The rate limiter is a fixed window, caching is exact-match, and the routing table is static. The lab proves where the controls sit and what they buy — it is not a production gateway.
